# dispatch — handoff, 2026-08-26

For the session running dispatch on the Godot project. Covers what changed since
that board was created, what to do about it, and where the bug report landed.

Everything here is in `main` at `git@github.com:GallagherSam/dispatch.git`.
429 tests, `python3 -m unittest discover -s tests -t .`

---

## Do this first — and it will not disturb the running board

`dispatch` is installed editable, so the source has already moved under you. The
running scheduler is **unaffected**: it re-reads `config.json` every tick, but it
is still executing the Python it was started with. Nothing below restarts it.

```bash
cd <the board's repo>
dispatch upgrade            # reports what is stale, with the reason. Writes nothing.
dispatch upgrade --apply    # writes it
```

Expect it to flag at least:

| setting | why |
|---|---|
| `sandbox.enabled: false → "auto"` | the whole of BUG 2 |
| `global_gates.pre_complete` gains `no_stray_writes` | catches BUG 2 when unconfined |
| `mutation.duplicate_review: 0.55` | uncertain duplicates get judged, not accepted |

**Then finish the current cards and restart**: `dispatch down && dispatch up -d`.

The distinction matters. Config changes take effect on the next tick. Code
changes — the sandbox, the new gates, the landing check — take effect on the
next **process**. `dispatch upgrade` says so when it sees a scheduler running.

One caution if you flip `sandbox.enabled` before restarting: whichever sandbox
code that process holds is what will run. If it predates the Seatbelt backend it
will reach for `srt`, which restricts network egress and will break `WebFetch`
for your agents. Cleanest order is apply → drain → restart.

## The bug report

### BUG 1 — a card passes its pipeline and never lands, silently

**Fixed.** You were right that it was the worst of the three, and right about the
fix. I had introduced it.

The dead state was exact: merge conflict → checkpoint → you approve → the card
goes `status=queued, stage=done`. `start_merge` only ever looks for
`status=merging`, so nothing picked it up again. It looked finished.

Two changes, because the second is the one that catches the paths I have not
thought of:

1. Approving a merge-failure escalation now checks whether the card still has
   commits its base branch does not, and returns it to `merging` if so.
2. **`done` is verified, not assumed.** Every card at `done` with a branch is
   checked against `base..branch` on a cadence
   (`runner.verify_landed_every_ticks`, default 20). One with commits left is
   put back into `merging` and logged as `merge.unlanded`. This also rescues the
   two cards already stranded on your board — they will be picked up on the
   first tick after you restart.

Writing that check I put a bug in it: `ticks % every != 1` never matches when
`every == 1`, so setting the interval to 1 turned the check off entirely. Found
by a test, fixed.

### BUG 2 — an unsandboxed agent writes into the base repo

**Fixed before your report, plus one thing from it.**

- `sandbox.enabled` defaults to `"auto"` — confine wherever the OS can
  (Seatbelt on macOS, bubblewrap on Linux; the internet is left alone), and say
  so plainly where it cannot rather than refusing to start.
- A `no_stray_writes` gate snapshots the repo's dirty paths around each run and
  returns the card with the exact list, so an agent claiming success gets sent
  back with what it actually did. This is the net for when confinement is off.
- A stalled merge escalates to a checkpoint naming the dirty files **and every
  card it is holding up**, instead of deferring quietly forever.

**Your `diff_scope` note is now fixed too.** The worktree's already-dirty paths
are recorded when it is cut and subtracted before the gate judges. Engine
sidecars that predated the card no longer get blamed on it. A genuine stray is
still caught, and the pass message says how many were discounted.

Your three hand-rescues should stop being necessary: with confinement on, the
write fails in the kernel rather than landing in the main checkout.

### BUG 3 — the expansion alarm

**Fixed, all three parts.**

- **Attribution.** It counts **agent-created** cards only. Cards you create —
  including ones you cancel and recreate while cleaning up a mess — are not the
  board expanding itself. Your audit was the argument: right about the number,
  wrong about the cause.
- **Pause vs crash.** `status` now shows `◐ scheduler paused` with the reason:

      ◐ scheduler paused (pid 4821)
        paused    expansion alarm — 14 agent-created card(s) per 5 completed
                  answer it in `dispatch needs`, or `dispatch resume`

- **It can actually be cleared.** Answering the alarm's checkpoint acknowledges
  it: the ratio window restarts from that point and the pause lifts. It used to
  be purely historical, so an answered alarm re-fired forever and the only way
  through was disabling the guard — exactly what you had to do. There is also a
  new `dispatch resume`.

### BUG 4 — `init` guessed a test command that does not exist

**Fixed before your report.** The detected command is now **run** before it is
stored, and a guess that does not work is not stored at all — refusing to guess
beats guessing wrong and looking healthy. A slow suite is not mistaken for a
wrong one: a wrong command fails in seconds, so a timeout stores it with a note
rather than discarding it. `--no-verify` skips the check.

`--test-cmd`, `--lint-cmd`, `--build-cmd`, `--auth`, `--sandbox` now update an
initialised board without `--force`, since `--force` also resets workflows and
agent prompts.

### Smaller friction

| item | status |
|---|---|
| no `unlink` | `dispatch unlink`, plus `dispatch edges` to see them |
| a cycle can be created | `link` refuses a cycle, and refuses a parent→child edge as a provable deadlock |
| `cancel` cascades silently | names every card it would destroy; children need `--cascade`, or `--only` |
| `ls` shifts columns | the id is always field 1, running is marked in the status column, and `--json` exists |
| `show` truncates the brief | says when it clipped, `--full` for all of it, and warns that an edit to a running card lands on its next attempt |
| proposals never carry criteria | `--accept` is now **required** for `add_task` and `split`, and agents are told so in their prompt |
| near-duplicates slip past 0.82 | similarity scores token overlap as well as characters, and a middle band (0.55–0.82) is judged rather than accepted blind |
| `merge.deferred` only in the log | `blocked` explains merge holds, and the reasons say what to do ("commit or stash them and it will land") |
| aggregate spend passed the ceiling | `containment.total_budget_usd` is enforced by `budget_remaining` and shown in `status` — the per-subtree ceiling was never a board ceiling |
| "the session's job ends when the board is set up" | corrected in `dispatch docs sessions` |

Your last point is the one I would keep saying out loud: **proposals arrive
needing a human, not fewer of them.** Requiring `--accept` should cut the traffic,
but the gate refusing an unfalsifiable card *is* the system working, and the docs
now say to expect checkpoints early rather than a quiet board.

## What is new since that board was created

### Direction instead of task lists

```bash
dispatch intent "Keys should be able to expire. I want a TTL on writes, and a
GET after expiry should behave exactly like a missing key. I do not care whether
expiry is lazy or swept, as long as memory does not grow without bound."
```

or **Describe work** in the board header. Pipeline is `spec → signoff`: a
`planner` agent reads the repo and proposes cards — brief, acceptance criteria,
scope, dependencies — plus risks and what it deliberately left out. `has_plan`
refuses a shapeless one before it reaches you. Approving creates the cards with
their edges and starts the unblocked ones; amending sends it back to be
re-planned with your objection attached.

The value showed up in the risks. On a live run the planner flagged that it had
guessed milliseconds where most KV stores take seconds — *"the one thing worth
vetoing at signoff"* — a one-line change before the work, a breaking change
after.

The new cards are deliberately **not** children of the direction card: a parent
waits for its children at its final stage, and the direction's final stage is
your approval, so parenting them would deadlock it the moment you said yes. They
carry `from:<id>` as a tag. `dispatch docs direction`.

### Shared memory

Every card starts a fresh agent with no history. Memories are searched using the
card's title, brief, tags and scope and **injected into the prompt** — an agent
that has to remember to look something up mostly does not.

```bash
dispatch memory add "The store has no expiry" \
  --body "src/store.js is a bare Map. Nothing evicts, so anything time-based
          has to be added there first." --tags store --kind gotcha
dispatch memory search "expiry"
```

Also at `/api/memory` (GET/POST/PUT/DELETE), and agents are given the URL.

Search is SQLite FTS5 with bm25 — no dependency, no model, no daemon. I looked
at chromadb and decided against it: it adds a large dependency tree to a tool
that currently has none, and repo facts are retrieved by their nouns (file
names, symbols, commands), which is what keyword search is good at. It will not
match a paraphrase sharing no words. Retrieval is one function if that trade
stops being worth it. `dispatch docs memory`.

**Seed it for this repo before the next run.** Two or three gotchas — the real
test command, the engine sidecar litter, whatever bit a card twice — will pay
for themselves immediately.

### Waiting from a session

`dispatch wait [ID...] --timeout N` blocks and returns with an exit code
(`0` landed, `1` failed, `2` timed out, `3` needs a human). It returns on a
checkpoint rather than hanging on something only you can move. `dispatch hook
stop` is a Claude Code Stop hook that hands the board's state back to a session
at the end of every turn. `dispatch docs sessions`.

### The board UI

The drawer header and actions are pinned. Agent-written markdown renders as
markdown instead of a `<pre>` blob — headings, lists, code, tables. Columns fill
the viewport under sticky headers with an edge fade where stages run off-screen.

## Worth knowing

- **Linux confinement is unverified.** The `bwrap` backend is written and
  unit-tested for argv shape, but I have only exercised Seatbelt on macOS.
- **The board has no login.** Loopback by default, cross-origin writes refused;
  on a tailnet your ACLs are the boundary. `dispatch up -d --host tailscale`
  binds to the tailnet address specifically, not `0.0.0.0`.
- **Ports are per-repo.** `server.port` defaults to `"auto"` — a stable hash of
  the repo path in 7777–7876, so several boards coexist.
- **Billing.** `runner.auth` defaults to `subscription` and strips the API auth
  variables from the agent's environment, because an `ANTHROPIC_API_KEY` outranks
  the claude.ai login. `status` says which credentials agents will use. The
  dollar figures are notional on a subscription — rate limits are the real
  ceiling, so teaching `.dispatch/gates/quota.sh` to print remaining percentage
  is worth the ten minutes.

## Open

- Nothing from the bug report is knowingly unfixed.
- `has_acceptance` remains the highest-value thing here and the sharpest risk is
  still acceptance-criteria quality. On a repo where the test command is
  `bash tools/run_tests.sh`, make sure `dispatch upgrade` or
  `dispatch init --test-cmd` has it stored and **verified** before the next run —
  a wrong one makes every completion gate meaningless while the board looks
  healthy.

`dispatch docs` for the manual; `dispatch docs troubleshooting` first when
something is stuck.
